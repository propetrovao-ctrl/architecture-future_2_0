## Языки и фреймворки

### Активно используем

- Python  
  Поддерживает ИИ-сервисы и анализ медицинских данных.

- Go / Java  
  Поддерживают финтех-сервисы, платежи, счета и кредиты.

### Выкидываем

- PowerBuilder  
  Поддерживает текущую работу операторов, но мешает развитию и удорожает поддержку.

## Платформы

### Активно используем

- Облачная инфраструктура  
  Нужна для масштабирования отчётности, раздельного развития доменов и подключения новых бизнесов.

### Пробуем

- Data Lakehouse  
  Нужен для быстрой аналитики, поддержки больших объёмов данных и единой платформы для BI и ИИ.

### Выкидываем

- Microsoft SQL Server 2008 как центр всей логики  
  Сейчас поддерживает отчётность и часть бизнес-логики, но стал узким местом.

## Практики и паттерны

### Пробуем

- Data Mesh  
  Нужен для независимого развития клиники, финтеха, ИИ и будущих партнёров.

- Доменные data products  
  Нужны для публикации данных без ручной сборки логики в DWH.

### Изучаем

- TIME для инвентаризации приложений  
  Нужен, чтобы решить, что инвестировать, что мигрировать, а что выводить.

## Инструменты

### Активно используем

- Power BI  
  Поддерживает текущую отчётность, но зависит от DWH и кастомизаций.

- Apache Camel ESB  
  Поддерживает текущие интеграции, но ограничивает скорость изменений.

### Пробуем

- Data Catalog  
  Нужен для поиска данных, lineage, контроля доступа и публикации data products.

- Портал самообслуживания  
  Нужен для быстрого доступа бизнеса к данным и отчётам.

- IAM / аудит / политики доступа  
  Нужны для качества медицинских и финансовых сервисов и соответствия требованиям.

- Стандартизированный ingestion  
  Нужен для быстрого подключения новых доменов и партнёров.

### Изучаем

- Airflow / оркестрация пайплайнов  
  Нужен для управляемой загрузки и трансформации данных.

- Dremio / слой self-service аналитики  
  Нужен как возможный инструмент для витрин и ad-hoc анализа.

- Nessie / Iceberg / MinIO  
  Нужны как возможные компоненты Lakehouse и управления данными.

### Выкидываем

- BI-логика и бизнес-логика внутри DWH  
  Мешают time-to-market и независимому развитию доменов.
