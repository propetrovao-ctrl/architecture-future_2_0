# Обоснование конфигурации

## Что развернули

Инфраструктура развернута в существующей сети `default`, потому что в учебном аккаунте ограничено количество VPC.

Terraform управляет:
- виртуальными машинами (`bastion`, `lakehouse`, `fintech-service`, `ai-service`);
- дисками;
- `Security Group`.

Сеть и подсеть используются готовые (предсозданные в облаке).

## Почему такие размеры VM и дисков

- `bastion`: 2 vCPU, 2 GB RAM.
- `lakehouse`: 2 vCPU, 4 GB RAM + data disk 20 GB.
- `fintech-service`: 2 vCPU, 4 GB RAM + data disk 20 GB.
- `ai-service`: 2 vCPU, 4 GB RAM + data disk 20 GB.
- для каждой VM отдельный boot disk 10 GB.

Это учебные размеры, чтобы пройти развёртывание в рамках квот.

Тип дисков выбран `network-hdd`, так как он укладывается в лимиты аккаунта.

## NAT и безопасность

- `bastion` имеет публичный NAT IP для администрирования.
- сервисные VM работают без публичных IP.
- SSH разрешен по `admin_cidr`.
- внутренний обмен между сервисами разрешен правилами `Security Group`.

Такой подход сохраняет доступ для админа и снижает внешний риск для внутренних сервисов.

## Почему Terraform и IaC

Terraform использует декларативный подход: описываем желаемое состояние, а инструмент сам строит шаги создания.

Плюсы IaC:
- одинаково воспроизводимые окружения
- быстрые изменения через переменные
- контроль изменений через `plan` и git
- меньше ручных ошибок.
